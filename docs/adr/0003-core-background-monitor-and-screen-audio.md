# ADR: 服务端后台性能记录与投屏音频

## 背景

Web 与 Android 客户端原先在页面内用定时器执行硬件采样。设备一次采样实测常需 2–2.5 秒，而移动端每秒启动一次新请求，离开页面又会销毁记录。这既不符合“仅手动停止”的记录语义，也会挤占快捷控制、伴侣检测和截图所需的 ADB 请求。

scrcpy 会话原先显式关闭音频，因此视频正常时也无法播放设备声音。

## 决策

1. 后台性能记录由 Go 设备服务拥有，独立于自动化任务 DSL；客户端只负责开始、停止、查询和导出。
2. 每台设备最多一个记录循环，采样严格串行。下一周期从上一次采样完成后计算，慢 ADB 不排队、不重入；离开页面只停止 UI 轮询。
3. Web 管理员 API 与受设备授权约束的远程用户 API 共享同一任务事实源。
4. 截图按设备单飞，优先尝试 Companion `accessibility.screenshot`；失败后进入一分钟冷却并使用 ADB。并发刷新返回明确忙错误，不建立请求积压。
5. scrcpy 开启 `raw` 音频，使用 48 kHz、16 位、双声道 PCM。WebSocket 协议 3 在协议 2 的时间戳包头上增加 `kind=3` 音频配置和 `kind=4` 音频数据；协议 1/2 视频客户端保持兼容。
6. Android 用 `AudioTrack`，Web 用 `AudioContext` 播放；音频不可用只降级声音，不终止视频与控制。

## 原因

服务端生命周期不受页面或移动进程导航影响；单飞采样直接消除日志中已经证实的 ADB 请求堆积。Raw PCM 不需要在浏览器或 Android 引入额外解码依赖，局域网带宽可接受。

## 替代方案

- 使用客户端前台服务保持记录：拒绝，Web 无等价生命周期且会产生多个事实源。
- 把记录建模为自动化任务：拒绝，它不是用户自动化流程，也不应受自动化调度状态机控制。
- 使用 Opus：暂不采用，需要额外浏览器封装或 Android 解码队列；后续可在协议能力协商中增加。

## 影响范围

Go 设备服务/API、Vue 硬件与投屏组件、Android 监控与媒体传输、Rust scrcpy 启动参数。

## 风险

部分 Android 版本或受 DRM 保护的应用禁止播放捕获；此时服务端标记音频不可用。Raw PCM 约占 1.5 Mbit/s，需要在公网场景后续提供 Opus。

## 未来演进

记录任务状态可进一步持久化以跨服务重启恢复；协议可增加 Opus 及音量/静音控制，但不得改变协议 1/2 视频语义。
